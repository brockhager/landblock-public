# Public Documentation Scope

This repository is public. Documentation published here must be safe for public
release and must not disclose private project details.

---

## Publishable Content

The following categories are appropriate for this repository:

- Vision, goals, and project framing
- High-level principles and conceptual models
- Public whitepaper material
- Non-operational architecture descriptions
- Roadmap summaries and public status updates
- FAQ, glossary, and other explanatory documentation

---

## Content That Must Stay Private

The following categories should not be published here:

- Source code or code excerpts from the private project
- Algorithms, protocol details, or internal logic
- Schemas, APIs, or interface definitions
- Infrastructure, deployment, or operational runbooks
- Security controls, threat handling details, or secrets
- Internal research notes, private decisions, or confidential planning
- Anything detailed enough to enable reimplementation

---

## Editorial Rule

When adding documentation, prefer explanation over specification.

If a document starts to answer how the system is built, operated, secured, or
implemented in concrete terms, it likely belongs outside this public repository.

---

## Review Standard

Before publishing content, ask:

- Is this useful to a public audience?
- Is this describing the project rather than exposing the project?
- Would this reveal implementation, operations, or security details?
- Would this materially help someone recreate internal work?

If the answer to either of the last two questions is yes, do not publish it.
